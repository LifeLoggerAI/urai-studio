# Studio short-form consent transport

The protected `/api/studio/video-factory/jobs-dispatch` create request now requires explicit canonical `consent` with exactly `purpose: life-movie.render`, `policyVersion` (1–80 trimmed characters) and `decisionReceiptId` (1–160 trimmed characters). The route forwards this context unchanged after normalization alongside its server-owned tenant and user; the protected client independently validates create consent before HTTP dispatch. Missing, malformed, wrong-purpose or extra-field consent never reaches Jobs. Per-source `consentRef` and `ownerOrRightsRef` remain separate required provenance fields and cannot substitute for the canonical render decision.

The prior Studio #159 dispatch omitted the context entirely even when the caller supplied it, while Jobs' strict create schema requires it. The actual-source HTTP reproduction returns `invalid_bridge_request` for an otherwise valid synthetic input. The new actual handler/client regression verifies accepted transport, server-owned identity, invalid-context denial, existing authentication/default-off behavior, malformed input and a canonical Jobs revocation rejection. It is discovered by the existing `tests/all.test.mjs`; no test/workflow/dependency gate is removed or bypassed.

This is transport compatibility, not creation or verification of a real consent grant. Jobs retains receipt binding, canonical revocation, source rights and execution authority. Dispatch remains off unless its existing protected configuration is explicitly enabled. Provider generation/public release flags remain false. No live provider, private source, deployed runtime, media acceptance, merge or production approval is established.
